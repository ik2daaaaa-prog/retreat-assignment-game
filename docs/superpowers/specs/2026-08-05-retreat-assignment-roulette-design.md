# 야유회 랜덤 배정 게임 설계

## 목표

야유회 현장에서 진행자가 참가자를 입력한 뒤 룰렛으로 운전자, 차량 좌석, 방, 설거지 담당을 공정하고 재미있게 정하는 단일 페이지 웹 게임을 만든다. 모든 데이터는 매번 화면에서 입력하며 브라우저에만 저장한다.

## 사용자 흐름

1. 진행자가 참가자 이름을 추가한다.
2. 운전자 룰렛으로 운전자를 한 명씩 뽑는다. 필요 인원이 채워질 때까지 `운전자 추가 추첨`을 반복하고 `운전자 확정`으로 다음 단계로 진행한다. 운전이 불가한 사람이 나오면 그 결과만 다시 뽑을 수 있다.
3. 확정된 운전자마다 소유 차량명을 입력한다. 이 목록이 실제 차량 수가 된다.
4. 각 차량의 좌석을 만들고, 남은 참가자를 빈 좌석에 룰렛으로 한 명씩 배정한다.
5. 차량 탑승이 끝나면 같은 참가자를 방 정원에 맞춰 룰렛으로 배정한다.
6. 마지막으로 설거지 역할별 담당자를 룰렛으로 배정한다.
7. 최종 결과를 차량/좌석, 방, 설거지 표로 확인하고 복사하거나 인쇄한다.

## 차량 및 좌석 규칙

- 운전석은 해당 차량의 운전자로 자동 고정한다.
- 차량명에 `카니발`이 포함된 차량은 3열 구조를 사용한다: 운전석, 조수석, 2열 왼쪽/오른쪽, 3열 왼쪽/오른쪽. 총 6석이다.
- 그 외 차량은 2열 구조를 사용한다: 운전석, 조수석, 2열 왼쪽/오른쪽. 총 4석이다.
- 모든 차량에서 가운데 좌석은 제공하지 않는다.
- 같은 차량명이 여러 번 입력되어도 운전자별 독립 차량으로 취급하고 화면에는 `운전자명 · 차량명`으로 표시한다.

## 화면 구성

- **준비 화면:** 참가자 목록, 이름 입력, 시작 버튼.
- **운전자 추첨:** 큰 룰렛과 추첨 결과 카드, 추가 추첨/결과 다시 뽑기/운전자 확정 버튼, 확정 운전자 목록.
- **차량 등록:** 운전자별 차량명 입력란과 자동 생성될 좌석 수 안내.
- **좌석 추첨:** 현재 뽑을 차량 좌석과 남은 후보를 표시하는 룰렛, 차량별 좌석 배치 결과.
- **방 및 설거지 추첨:** 동일한 룰렛 인터페이스와 현재까지의 결과판.
- **최종 결과:** 차량별 운전자 및 좌석, 방별 투숙자, 역할별 설거지 담당자를 구분한 표. 복사/인쇄/전체 초기화 제공.

## 상태와 데이터 흐름

- React 상태는 `participants`, `drivers`, `vehicles`, `assignments`, `rooms`, `chores`, `phase`로 나눈다.
- `vehicles`는 운전자 확정 이후 생성하며, 차량명으로부터 좌석 템플릿을 계산한다.
- 차량 좌석 룰렛 후보는 운전자를 제외한 미배정 참가자만 사용한다. 방 배정은 별도의 배정 결과이므로 전체 참가자를 다시 후보로 사용한다.
- 설거지는 역할 수가 참가자 수보다 많아도 진행할 수 있으며, 한 사람이 복수 역할을 맡을 수 있다.
- localStorage에 입력 내용과 진행 상태를 저장하고, 초기화 시에만 삭제한다.

## 예외 처리

- 운전자를 한 명 이상 확정하지 않았거나 차량명이 비어 있으면 좌석 배정을 시작할 수 없다.
- 남은 좌석 수가 미배정 참가자 수보다 적으면 게임을 멈추고 부족 인원을 표시한다. 진행자는 운전자를 추가 추첨하거나 차량 정보를 수정한다.
- 남는 좌석은 빈자리로 남긴다.
- 각 단계는 이전 단계로 돌아갈 수 있으며, 현재 배정만 다시 추첨할 수 있다. 이후 단계의 결과는 이전 단계를 수정할 때 무효화한다.

## 기술 구조

- 단일 클라이언트 React 페이지와 CSS로 구현한다.
- 룰렛 애니메이션은 브라우저에서 실행하며, 최종 선택은 균등 무작위 방식으로 결정한다.
- 외부 API, 계정, 서버 또는 데이터베이스는 사용하지 않는다.
- UI는 모바일과 데스크톱에서 진행자가 조작하기 쉬운 큰 버튼과 높은 대비를 제공한다.

## 검증

- 참가자 입력, 운전자 재추첨, 차량명 입력, 좌석 자동 생성 흐름을 테스트한다.
- 카니발에는 3열 6석, 일반 차량에는 2열 4석만 생성되는지 확인한다.
- 가운데 좌석이 생성되지 않는지 확인한다.
- 좌석 부족 시 진행이 차단되고 안내가 표시되는지 확인한다.
- 단계별 후보 제외 및 방/설거지 후보 재사용 규칙을 확인한다.
- 새로고침 뒤에도 데이터와 진행 상태가 복원되는지 확인한다.
- production build 및 정적 렌더 테스트를 통과시킨다.
